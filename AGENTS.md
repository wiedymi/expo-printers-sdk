# AGENTS.md

## Project

`expo-printers-sdk` is an Expo native module that prints receipt images on Epson, Star Micronics and Rongta printers, and reads printer status. It supports Android only. The `ios/` folder has a placeholder only. The package is published to npm as `expo-printers-sdk`.

## Layout

- `src/`: TypeScript API. One `*PrintersModule.ts` and one `*.types.ts` per vendor. Shared types are in `commons.ts`. `build/` is generated by `tsc`. Do not edit it.
- `android/src/main/java/expo/modules/printers/`
  - `*PrintersModule.kt`: Expo module definitions (the JS API). The `to*DeviceData()` helpers convert the JS printer object to `PrinterDeviceData`.
  - `commons/`: shared code. `Printer` interface (`printImage`, `getStatus`), `PrinterDeviceData`, `PrintOptions` and `PaperWidth`, `PrinterStatus` and the status exceptions.
  - `epson/`, `starmicronics/`, `rongta/`: vendor code. Model tables are in `internals/`.
- `android/libs/` and `android/src/main/jniLibs/`: vendor binaries (Epson ePOS SDK 2.33.2, Rongta library, android-serialport-api). The Star SDK comes from Maven Central (see `android/build.gradle`).
- `example/`: Expo test app. It uses the library from `..` through autolinking. `example/android` is generated and is not in git.
- `CHANGELOG.md`, `LICENSE`, `THIRD_PARTY_NOTICES.md`, `licenses/`.

## Commands

Use Bun only. Do not add `package-lock.json` or `yarn.lock`.

- Install: `bun install` in the root and in `example/`.
- Build the TypeScript: `bun run build`.
- Format: `bun fmt`, check with `bun fmt --check`.
- Lint: `bun lint` (Bun's built-in linter, Bun 1.4.5 or later).
- Compile the Android code:

  ```bash
  cd example && bun install && bunx expo prebuild -p android --no-install
  cd android && ./gradlew :expo-printers-sdk:compileDebugKotlin
  ```

  Use `./gradlew assembleDebug` for a full app build. If CMake fails with glog header errors, unset `CPATH` for the build.

There are no unit tests. Test changes to printing or status on real printers with the example app ("Print Test" and "Status" buttons). Read logcat with the tags `EpsonPrinter`, `StarMicronicsPrinter` and `RongtaPrinter`.

## Rules

- Pin dependencies to exact versions. Keep `peerDependencies` open.
- The library uses the `compileSdk` of the app (36 for Expo SDK 58). Do not use library versions that need a higher `compileSdk`. For example, Star `stario` 2.14.3, `starioextension` 1.17.1 and `core-ktx` 1.19 need 37.
- `printImage` returns at once and sends the result in the `onPrintImage` event. `getStatus` returns the result in the promise (`AsyncFunction ... Coroutine`) and rejects with `CodedException` subclasses (`ERR_PRINTER_UNREACHABLE`, `ERR_PRINTER_BUSY`, `ERR_PRINTER_STATUS_UNAVAILABLE`). Run blocking SDK calls on `Dispatchers.IO`.
- Images fit the printable width of the printer: `EpsonModelCapability.printableWidth`, `StarModelCapability.getPaperSize` and the Rongta `bimtapLimitWidth`. The values come from vendor manuals. If sources disagree, use the smaller value, because an image wider than the print area can print nothing.
- Rongta connections use `RongtaPrinter.connect()` and `disconnect()` under `printMutex`.
- Do not change vendor binaries. When you add, update or remove a third-party component, update `THIRD_PARTY_NOTICES.md` and `licenses/`.
- Add each change that users can see to the `Unreleased` section of `CHANGELOG.md`.
- Write commit messages on one line.
- Releases: the workflow `.github/workflows/npm-publish-github-packages.yml` runs on a `v*.*.*` tag or by hand with a version. It installs with Bun and publishes to npm with trusted publishing.
